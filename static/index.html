Google Sheets

Each office's New Patient Analysis sheet is read with a read-only service account. Only counts are saved here; patient rows stay in Google.

1. Connect to Google

The app reads each office's sheet with a read-only Google service account. It never changes the sheets. Patient rows stay in Google; only the counts are saved here.

Setup steps (one time, about 15 minutes)
  1. Go to console.cloud.google.com, sign in with your Care Dentistry Google account, and create a project (e.g. "Monthly Report Reader").
  2. In APIs & Services → Library, search Google Sheets API and click Enable.
  3. In APIs & Services → Credentials: Create credentials → Service account, name it (e.g. "report-reader"), click Create and continue, skip the optional steps, Done.
  4. Open the new service account → Keys → Add key → Create new key → JSON. A .json file downloads. Keep it private — it's the app's password to read the sheets.
  5. Add that file below with Add key file. It's stored only on this computer, in the git-ignored data/ folder.
  6. For each office sheet: Share → paste the service account email shown above → Viewer → untick "Notify" → Share. Then add its link under 2. Office sheets.

If Google says key creation is blocked by your organization's policy, your Workspace admin needs to allow it for this project. If a file shows an .XLSM badge in Drive, it's an Excel file, not a Google Sheet: open it and use File → Save as Google Sheets, and share the new sheet.

3. Sync

Load past months

The regular sync reads each sheet's newest 2 month tabs. To fill in older months, load every month tab from a start month on (New Patient Analysis and refunds). Past months only get the sheets' numbers; collections, new patients and the rates that use them need those months' Denticon reports uploaded. This can take a few minutes.

The app keeps a Google Sheet copy of the Log, one tab per month like the platform (newest first, same columns, with a Total row), updated within about 2 minutes of any change. Create a blank Google Sheet, share it with as Editor, and paste its link here. Type your notes in its Notes column; everything else is rewritten by the app. Only on this computer.

Denticon API

Connect the app to Denticon with your API subscription key, so it can read the offices' ledgers (lender payments and fees) every night instead of uploading Daily Journals. The key is stored only on this computer (in data/, readable only by your user) and is never shown again.

Invoca API (call tracking)

Connect the app to Invoca so it can read call data (calls per office and campaign, durations, signals) with the Transactions API. In Invoca: Integrations → Manage Integrations → Invoca APIs → + New API Credential. The site name and ID are in your Invoca address: for https://acme.invoca.net/networks/99/… the site is acme, the type Network and the ID 99. Everything is stored only on this computer (in data/, readable only by your user); the token is never shown again. Callers' phone numbers are never requested.

Assistant (Claude API)

The Ask button (bottom right, for everyone including the view-only link) answers questions about the Log, Charts and Calls. It can only look numbers up, never change anything, and its lookups return totals only (no patient names, IDs or phone numbers). Paste your Claude API key from console.anthropic.com below; it's stored only on this computer (in data/, readable only by your user) and never shown again. Every question is logged below for review.

To keep costs down, each question goes through cheaper steps first: a question asked before reuses its saved answer (until the data changes) at no cost; greetings and clearly off-topic questions are handled by keyword rules at no cost; unclear ones get a quick yes/no check from Claude Haiku (a fraction of a cent); only real questions reach Claude Sonnet.

Google Drive

The assistant can search and read Google Docs, Sheets and Slides that are shared with the app's Google account (the same one the office sheets use). It sees only what you share. To add a folder or file: in Google Drive, click Share, add the app's Google account as Viewer, and untick "Notify people". Anyone using the chat (including the view-only link) can ask about what's shared.

Tables and columns

Table office_summary: office, period_from, period_thru, total_collection, insurance_collection, new_patients, np_first_visit, existing_patient_referrals, total_production, source_file, logged_at. Dates are YYYY-MM-DD. One row per office per month. Older versions of replaced or deleted rows are in office_history (same columns plus action, action_at).
Pasted sheet values (refunds), NP collection (Referral Production Listing) ortho collection (Daily Journal, Ortho) and ortho_referrals (Treatment Plan Status, ZREFORTH), medi_cal_patients, hmo_patients, no_ssn_itin_patients, financing_applicants, existing_finance_patients, prime_applicants, prime_approved, prime_apps_ran, prime_apps_approved, prime_approved_amount, prime_collected_amount, prime_funded, prime_approved_funded, subprime_applicants, subprime_approved, subprime_apps_ran, subprime_apps_approved, subprime_approved_amount, subprime_collected_amount, subprime_funded, fin_approved, fin_funded and fin_approved_funded (New Patient Analysis) are in office_metrics (office, period_from, as_of, metric, value), with history in metric_history. monthly_log combines both, the same as the Log tab, plus calculated net_collections (total − refunds), refund_rate (refunds ÷ total, a fraction), existing_pt_collection (total − NP collection) and irrelevant_rate ((Medi-Cal + HMO + no SSN/ITIN) ÷ new patients, a fraction) and ortho_rate (ortho referrals ÷ new patients, a fraction) financing_rate (financing applicants ÷ new patients, a fraction) prime_approval_rate (prime approved ÷ prime applicants), prime_collected_rate (prime $ collected ÷ approved), and the averages avg_prime_per_approved_np, avg_prime_per_approved_app, avg_prime_per_app_ran and avg_prime_per_applicant. Sheet-name matches are in office_alias.

How to use the Executive Summary Logger

Step 1 · Pull the reports from Denticon

Each month, run these reports in Denticon for the month you're logging (set the dates to that month) and save them as PDF or Excel. Then upload them in Step 2.

Executive Summary

Gives: total collection, insurance collection, new patients (new patients by first visit date − existing-patient referrals), total production.

Reports›Reports (Old)›Group Reports›Daily Report

Refunds

Gives: refunds for each office.

Nothing to pull: refunds come from the % TO GOAL Google Sheet, which is connected and updates by itself every 15 minutes (each month tab counts for its own month).

NP collection · Referral Production Listing

Gives: new patient collection for each office.

Reports›Referral Reports›Referral Production List
  • Select all offices, click Group by Zip Code and set the dates.

Ortho collection · Daily Journal

Gives: ortho collection for each office.

Daily Report›Daily Journal
  • Select all Ortho, then Pay to Adjustment.
  • Make sure Patient Type is Ortho (not Both); the app refuses a journal that includes general patients. Save it as PDF or Word (.doc).

Lender check · Daily Journal (all patients)

Checks each new patient's financing on the NP sheets against what the lenders actually paid in Denticon.

Daily Report›Daily Journal
  • Set Patient Type to Both and Transactions to Payments, Adjustments (the adjustments carry the lenders' fees), the whole month, all offices. Save as PDF or Word and upload it once a month.
  • The results are on the Audit tab, which only shows on the computer that runs the app.

# of ortho referrals · Treatment Plan Status

Gives: number of ortho referrals for each office.

Reports›TP Report›Treatment Plan Status
  • Select all of the offices and choose Other → Ortho Referral.

New Patient Analysis

Gives: Medi-Cal / HMO / no SSN-ITIN patients, financing (prime and subprime), treatment diagnosed and started.

Each office keeps its own workbook. Offices with a connected Google Sheet update by themselves every 15 minutes; for the others, upload the office's workbook (.xlsx or .xlsm).

Step 2 · Upload the reports

  1. Open the Upload tab and drag the report onto the box, or click the box to choose the file (.pdf, .xlsx, .xlsm, or Word .doc / .docx). The app recognizes which report it is.
  2. Check the review table. Numbers with a dotted underline can be hovered or clicked to see exactly what was counted (sheet rows, never patient names).
  3. Check Period from and Period thru. PDFs fill them in; Excel exports don't include dates, so pick the Thru date and From becomes the 1st of that month.
  4. Untick any office you don't want, then click Save to log. Uploading the same report again for the same month replaces the older numbers (the old ones are kept in history).

Date rules: the Thru date can't be in the future. If the log already has a later report for that month, the older one is skipped. If any number is lower than what the log has (month-to-date numbers usually only go up), or a same-date report changes a number, you'll see a Check before saving list: check the report and its dates, then click Save anyway or Cancel.

⚠ If a warning appears above Save, a value looks wrong (see Step 4). You can still save; it will be flagged in the log.

Don't upload a New Patient Analysis for an office whose Google Sheet is connected; the sync keeps it up to date.

Day by day: run the Executive Summary (and, if you want them by day, the Referral Production Listing, ortho Daily Journal and Treatment Plan Status) with From and Thru set to the same day, one file per day. These go to the day-by-day history, not the monthly row, and the Log's Days view adds any run of days up. The Inbox folder on this tab imports files saved into it by itself.

Step 3 · Read the log

  • The Log tab has one row per office per month. Use ◀ Month ▶ to change the month, or pick All months.
  • Days (next to Month) shows any run of days, from one-day reports added up per office: pick From and To. A row says how many of the days it has; hover the period for the missing ones. Only the numbers that come from daily reports show.
  • Sections switches show or hide groups of columns (Executive Summary, Collections, Ortho, Prime…). Columns and Office order let you rearrange them; your layout is remembered in this browser.
  • Click a column header to sort. The Total row at the bottom adds up the offices shown (rates are calculated from the totals, not averaged).
  • Hover or click a dotted number to see the sheet rows behind it. “as of 09/28” is the date that number was last updated.
  • Copy puts the rows and columns shown on your clipboard for Excel or Google Sheets.
  • The Charts tab is a collections report by ZIP code for any office and month range: headline totals, dollars per month, the top ZIPs, the map, the top 10 month by month, every ZIP as a sortable table, and each office's biggest ZIPs. A month loaded only part-way is marked and left out of the counts. Hover a bar for what's behind it; click a ZIP to see it on the map.
  • The map shows where a month's new patients live: each ZIP code area is colored by the measure you pick, with your offices as numbered pins and only the cities that have patients or an office named. Hover a ZIP area for its Pat IDs and $ collected. It fills from the Referral Production Listing when it's run grouped by Zip Code and saved as Excel.
  • The Calls tab starts with the funnel for a call month: calls, answered, callers who became new patients, who started treatment, and $ collected, broken down by promo line, office or campaign. Below it, one day's phone calls from Invoca as a sheet: pick the day, click Pull this day (or Pull whole month) once, then sort, filter, search and Copy. At the bottom, Promo lines → offices: tell the app once which office each Invoca line belongs to, and calls get an office. Upload Denticon's New Patients List for each office now and then (or the New Patients Through Appointment Book) and the "New patient?" column shows which callers came in as new patients, with the $ collected, or booked a first appointment (phone numbers are matched as fingerprints, never kept). Invoca is connected on the Audit tab (this computer only).
  • The Changes tab lists every number that was added or changed, when, and from which report.
  • A Google Sheet copy of the Log can be kept up to date for notes (Google Sheets tab › Notes sheet, on the computer that runs the app). Type notes in its Notes column; they stay with the right office and month.

Step 4 · Benchmarks and data checks

Benchmark colors

  • ● green on target, ▲ yellow close, ▼ red below target.
  • A ◎ in a column header means it has a benchmark; hover it to see the cut-offs. The Benchmarks button shows them all and lets you change them (same for every office).

Data checks ⚠

  • A ⚠ means a value looks wrong: a rate over 100%, or a patient with more collected than approved. Hover it to see why. The number is still counted as the sheet has it until the office fixes the sheet.
  • Click Checks to see the list. For each one you can: Mark OK with a short note if it's correct, Email office to open a ready-made email in your email app listing what to fix (you review it and press Send), or Copy message for Teams or Chat.
